## Контекст

План предполагал, что строгий JSON для всех моделей получим одинаково, через tool use с принудительным `tool_choice`.

## Решение

Код показал, что для `claude-sonnet-5-5` и старших моделей 5.x (`opus-5-5`, `fable-5-1`) API отвечает на принудительный `tool_choice` ошибкой 400. Для этих моделей стоит `tool_choice: auto`, `strict: true` в схеме инструмента и требование вызвать инструмент в промпте. Для остальных моделей, включая `claude-haiku-5-5`, выбор инструмента остаётся принудительным.

## Почему

- **Принудительный `tool_choice` для всех моделей** не работает: модель по умолчанию отвечала бы 400 на каждом запросе.
- **Отказ от tool use и разбор JSON из текста** отвергнут: пропала бы проверка по схеме, и формат ответа держался бы только на промпте.
- **Только `auto` для всех моделей** не стали делать: там, где принудительный выбор работает, он надёжнее, и терять эту гарантию незачем.

## Последствия

- В модуле `ai` теперь две ветки, и выбор между ними зависит от имени модели. Каждую новую модель придётся вручную отнести к одной из них, иначе запрос может упасть с 400.
- При `auto` модель может в принципе ответить текстом и не вызвать инструмент. Такой ответ превращается в ошибку `bad-response`, и пользователь видит «Повторить».
- Тесты с подставным `fetch` не ловят изменений на стороне API. Если API поменяет поведение, это обнаружится только на живом запросе.
