## Что должно заработать

Три чистых модуля без интерфейса, которые потом подключит таск 03:
- `ai` разговаривает с Anthropic Messages API прямо из браузера с ключом
  пользователя и возвращает строго типизированный результат для трёх режимов:
  фото еды (позиции с граммами и КБЖУ), фото этикетки (таблица пищевой
  ценности как она есть: на 100 г / 100 мл / на порцию, ккал или кДж, масса
  порции/упаковки, название), фото штрих-кода (цифры). Не еда / не читается →
  `{ ok: false, reason }` с причиной по-русски («таблица обрезана снизу»).
  Ошибки HTTP и сети превращаются в `AiError { kind }`.
- `foodfacts` ищет штрих-код в Open Food Facts и отдаёт значения на 100 г или `null`.
- `image` сжимает фото на canvas (1568 px по длинной стороне, JPEG 0.85) в base64.

Главное в этом таске — этикетка. Ради неё всё и затевается: Yazio таблицу без
штрих-кода не читает. Промпт должен требовать переписать значения из таблицы,
а не оценивать их; если есть две колонки (на 100 г и на порцию), брать 100 г.

## Критерии приёмки

- [ ] Запрос: `POST https://api.anthropic.com/v1/messages`, заголовки `x-api-key`, `anthropic-version`, `anthropic-dangerous-direct-browser-access: true`; картинка base64; tool use с принудительным `tool_choice` на каждый режим; модель из `cfg.model`
- [ ] `analyzeFood` передаёт `hint`, если он задан; возвращает items либо `{ok:false, reason}`
- [ ] `readLabel` возвращает поля ровно по §3 (без нормализации); `readBarcode` возвращает только 8–14 цифр, иначе `ok:false`
- [ ] `AiError.kind`: no-key (пустой ключ, без запроса), bad-key (401/403), rate (429/529), network (fetch бросил), bad-response (нет tool_use / мусор)
- [ ] `checkKey(cfg)` — дешёвый запрос, true/false или AiError
- [ ] `lookupBarcode`: kcal из `energy-kcal_100g`, иначе `energy_100g/4.184`; status 0 / нет nutriments → null
- [ ] Тесты с подставным fetch: успешный ответ каждого режима, каждый kind ошибки, разбор OFF (с ккал, только кДж, не найден)
