# Спецификация: КБЖУ по фото

## Задача

Я хочу считать калории, белки, жиры и углеводы, не вбивая цифры руками. В Yazio
ИИ есть, но, когда я фотографирую заднюю этикетку с таблицей пищевой ценности,
он её не считывает. Работает только штрих-код, а если штрих-кода нет, всё
приходится вводить вручную. Это бред.

## Решение

Приложение на iPhone, которое ставится на экран «Домой» и открывается как
обычное. Главный экран «Сегодня» показывает, сколько калорий осталось до нормы
и сколько набрано белков, жиров и углеводов, а под этим идёт список съеденного
по приёмам пищи. По кнопке «+» можно:

- **сфоткать еду**: ИИ сам узнаёт, что на тарелке, и оценивает вес и КБЖУ;
- **сфоткать этикетку**: ИИ читает таблицу пищевой ценности, ты вводишь только
  граммы;
- **сфоткать штрих-код**: ИИ читает цифры, продукт ищется в открытой базе
  Open Food Facts;
- **выбрать из недавних**: тап по продукту, который уже попадался, открывает экран граммов с прошлым количеством, остаётся нажать «Сохранить»;
- **ввести вручную**: только запасной вариант.

Перед сохранением результат всегда можно поправить. Все данные хранятся на
телефоне, ИИ работает через собственный ключ Claude пользователя.

## Решения по реализации

**§1. Платформа.** PWA: статические HTML, CSS и JS на ES-модулях, **без сборки и
без npm-зависимостей**. Так ничего не нужно устанавливать, проект можно разместить
на любом статическом хостинге и открывать в Safari на iPhone. Service worker
кэширует оболочку приложения, без сети недоступно только распознавание.

**§2. Камера.** `<input type="file" accept="image/*" capture="environment">` для
съёмки и отдельный input без `capture` для галереи. Этот способ работает в iOS
Safari и не требует getUserMedia. Перед отправкой фото уменьшается на canvas до
1568 px по длинной стороне и сжимается в JPEG качества 0.85: это быстрее,
дешевле и в пределах рекомендованного размера картинок для Claude.

**§3. ИИ.** Запросы идут к Anthropic Messages API прямо из браузера (заголовок
`anthropic-dangerous-direct-browser-access: true`) с ключом пользователя.
Своего сервера нет, ключ никуда, кроме Anthropic, не уходит. Модель по умолчанию
`claude-sonnet-5-5`, в настройках можно выбрать дешёвую `claude-haiku-5-5`.
Строгий JSON получаем через tool use с принудительным `tool_choice`: одна схема
инструмента на каждый режим (еда, этикетка, штрих-код). *(Таск 02, D01: для
claude-sonnet-5-5 и старших моделей 5.x (opus-5-5, fable-5-1) API отклоняет принудительный `tool_choice`, поэтому там
стоят `auto` + `strict: true` + требование вызвать инструмент в промпте.)* Промпты на русском,
названия продуктов тоже возвращаются по-русски. Есть три режима:

- `analyzeFood(image, hint)` возвращает `{ ok: true, items: [{ name, grams, kcal, protein, fat, carbs }] }` или `{ ok: false, reason }`;
- `readLabel(image)` возвращает `{ ok: true, name|null, basis: "100g"|"100ml"|"portion", per: { kcal, protein, fat, carbs }, portionGrams|null, packageGrams|null, energyUnit: "kcal"|"kJ" }` или `{ ok: false, reason }`; нормализацию до ккал и на 100 г делает модуль `nutrition`, а не модель;
- `readBarcode(image)` возвращает `{ ok: true, code }` (8–14 цифр) или `{ ok: false, reason }`.

Ошибки переводятся в типы: `no-key`, `bad-key` (401/403), `rate` (429/529 и прочие 5xx — сервис временно недоступен, можно повторить),
`network`, `bad-response`. Для каждого типа есть своё сообщение по-русски.

**§4. Норма.** Базовый обмен по Миффлину — Сан-Жеору; коэффициенты активности
1.2, 1.375, 1.55, 1.725, 1.9. Цель: сбросить −15 %, держать 0, набрать +10 %.
Белок 1.8 г/кг при сбросе и наборе, 1.4 г/кг при «держать». Жиры 0.9 г/кг.
Углеводы — остаток калорий / 4, но не меньше 0. Округление: ккал до 10, граммы
до целых.

**§5. Хранилище.** IndexedDB, все данные на устройстве. Хранятся записи
(`entries`, по дате `YYYY-MM-DD` в локальном времени), недавние продукты
(`products`, по нормализованному имени без регистра, с последним использованием)
и настройки (`settings`: ключ, модель, профиль, норма, флаг ручной нормы).
Фото не хранятся.

**§6. Штрих-код.** `https://world.openfoodfacts.org/api/v2/product/{code}.json?fields=product_name,product_name_ru,nutriments,serving_quantity,product_quantity`.
Ключ не нужен. Берутся `energy-kcal_100g` (если его нет, `energy_100g` / 4.184),
`proteins_100g`, `fat_100g`, `carbohydrates_100g`.

**§7. Запись в дневнике.** Хранится уже посчитанной на съеденное количество, а
рядом лежат значения на 100 г, если они известны: так при правке граммов можно
пересчитать.

```ts
type Entry = { id: string; date: string; meal: "breakfast"|"lunch"|"dinner"|"snack";
  name: string; grams: number|null; kcal: number; protein: number; fat: number; carbs: number;
  per100: { kcal: number; protein: number; fat: number; carbs: number } | null;
  unit: "g"|"ml"; // таск 01: для правки продуктов «на 100 мл»
  portions?: { count: number; perPortion: { kcal: number; protein: number; fat: number; carbs: number } };
  source: "photo"|"label"|"barcode"|"recent"|"manual"; createdAt: number };
```

Если этикетка даёт значения только на порцию и масса порции неизвестна,
`normalizeLabel` возвращает `per100: null` и `perPortion`. Тогда экран
спрашивает число порций вместо граммов. Запись сохраняется с `grams: null`,
`per100: null` и `portions: { count, perPortion }`, а КБЖУ считаются как
`perPortion × count`. При правке меняется число порций.

**§8. Язык и вид.** Весь интерфейс на русском. Светлая и тёмная тема следуют
системной. Нижняя панель с вкладками «Сегодня» и «Настройки», в центре большая
кнопка «+».

## Границы и швы

| Модуль | Владеет | Выставляет | Прячет |
|---|---|---|---|
| `nutrition` | вся арифметика КБЖУ | `scale(per100, grams) -> Macros`, `sumMacros(list) -> Macros`, `normalizeLabel(labelResult) -> { per100\|null, perPortion\|null, unit: "g"\|"ml", suggestions: number[] }` (кДж→ккал, порция→100 г, если масса порции известна), `calcGoal(profile) -> Macros`, `mealByHour(hour) -> Meal`, `round(macros) -> Macros` | формулы, округление |
| `ai` | разговор с Claude | `analyzeFood(img, hint, cfg)`, `readLabel(img, cfg)`, `readBarcode(img, cfg)`, `checkKey(cfg)`; `cfg = { apiKey, model, fetch? }`; кидает `AiError { kind }` | промпты, схемы инструментов, HTTP, разбор ответа |
| `foodfacts` | Open Food Facts | `lookupBarcode(code, fetch?) -> { name, per100, servingGrams\|null, packageGrams\|null } \| null` | URL, разбор полей |
| `store` | IndexedDB | `listEntries(date)`, `saveEntry(e)`, `deleteEntry(id)`, `listProducts(query)`, `upsertProduct(p)`, `getSettings()`, `saveSettings(s)`, `exportAll() -> json`, `importAll(json)` | схема БД, миграции |
| `image` | подготовка фото | `prepareImage(file) -> { base64, mediaType }` | canvas, сжатие |
| `ui` | экраны и навигация | — (точка входа `app.js`) | всё остальное |

Тестовые швы: `nutrition` (чистые функции), `ai` и `foodfacts` с подставным
`fetch`. Тесты запускаются через `node --test` без зависимостей. `store`,
`image` и `ui` проверяются ручным прогоном в браузере.
